## Why

铁路货车轮轴的检修信息当前靠纸质卡片流转，履历易丢失、数据不准确。MVP 第一优先级是给每根轮轴建立"数字身份证"，解决"轮轴在哪、修过几次、什么状态"的核心痛点，并为后续工位采集、生产调度、故障预警模块打地基。这是四个模块里唯一不依赖外部数据源、可独立落地的地基模块。

## What Changes

- 新增「轮轴数字身份管理」能力：为每根轮轴建立全局唯一 ID（格式 `AX-YYYYMMDD-NNN`）与数字身份证（基础信息 + 关键检测指标）。
- 建立轮轴**双状态模型**，取代 prototype 中混用的单一"状态"字段：
  - `lifecycle_status`（生命周期状态）：在役 / 检修 / 报废
  - `repair_status`（检修流程状态）：在修 / 待复检 / 待验收 / 已出库（仅在生命周期为"检修"时有意义）
  - `alert`（派生预警标志，非状态）：参数超标 / 超期未修 / 临近报废
- 全生命周期履历管理：记录五类事件 —— 生产出厂登记 / 装车上线 / 复检处理 / 修复验收 / 报废。
- 报废状态管理：标记报废轮轴，使其不流入生产环节。
- 状态更新：支持在轮轴详情页手动更新状态（对应 prototype 的"更新状态"按钮）。

**非目标（本次不实现）**

- 新建轮轴的基础信息录入表单：prototype 无对应页面，MVP 假设轮轴数据由外部系统（HCCBM 入向）或初始导入灌入；唯一 ID 在导入时生成。
- 真实国铁系统对接：HMIS / HCCBM 仅保留接口抽象，用 mock 数据。
- 移动端：仅 PC 端。
