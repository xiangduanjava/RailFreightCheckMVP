## Why

「轮轴数字身份」能力已落地后端与前端，`Axle` 实体上已有四个关键检测指标字段（轮径磨损 wear、裂纹深度 crack、振动值 vibration、温升 temp），但 `AxleService.toEntity` 明确把它们留空、标注「由设备采集模块后续覆盖」——也就是说系统至今没有任何入口能写入检测数据，轮轴详情页的关键检测指标永远是空的。这是 MVP 第二优先级模块「工位数据自动采集与同步」要补的第一环：先用手动补录把检测数据打通，让「检测数据」真正进库、可查、可共享。

## What Changes

- 新增「工位数据手动补录」：在设备采集页支持对某根轮轴，按工位手动录入检测数据（轮径磨损 / 裂纹深度 / 振动值 / 温升），覆盖尚未自动化的工位场景。
- 新增「检测即上传」实时同步：补录提交后立即写入云端数据库，并回写该轮轴的最新检测指标、最近检测来源与一条「检测记录」履历，数据即时共享，无需后续人工二次上传。
- 新增「补录完整性校验」：自动校验必填数据（轮轴、工位、检测时间、工位对应的必填检测项）是否完整，不完整时弹窗提示缺失项并拒绝提交，避免漏检漏录。
- 新增「采集同步记录」：记录每条采集/同步事件（工位、轮轴、检测时间、检测值、同步状态），并按时间倒序展示。
- 前端启用「设备采集」导航项，重写 `prototype/device.html` 为 Vue3 页面（采集页 + 手动补录表单 + 同步记录 + 数据上传状态）。

**非目标（本次不实现）**

- 硬件设备对接（轮对尺寸检测机、超声波探伤仪等设备的自动读取）不做，本模块只做手动补录。
- 自动称重系统的重量数据不做（轮轴实体暂无重量字段）。
- 移动端（手持 APP / 小程序）不做，MVP 只做 PC 端。
- 断网本地缓存、联网后自动重传不做（PC 端为实时同步，无离线队列）。

### New Capabilities

- `station-data-collection`: 工位数据手动采集、实时云端同步与数据完整性校验能力，覆盖检测数据从采集到共享的闭环。

## Impact

- 后端 `backend/`：新增检测记录实体与表结构、采集记录仓储、手动补录接口（写入检测记录 + 回写 `Axle` 检测指标/最近检测来源 + 写检测履历）、新增履历事件类型（检测记录）、同步记录查询接口。
- 前端 `frontend/`：新增设备采集页（重写 `device.html`）、手动补录表单与完整性校验弹窗、`/device` 路由、启用侧边栏「设备采集」导航、新增采集 API 封装。
- 规格 `openspec/specs/station-data-collection/spec.md`：新增能力规格（手动补录、实时同步、完整性校验、同步记录）。
- 数据模型决策（检测记录表结构、工位枚举、必填项映射、回写规则）固化在 design.md。
